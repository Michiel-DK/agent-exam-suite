Small local models, measured on office tasks

Eight agents (seven in the hosted comparison), 220 committed cases, deterministic grading with no LLM judge, every candidate sat the same held-out cases at temperature 0. How it works in four steps, then three findings, one chart, one command.

Scores are held-out cases passed, never percentages. Dollars are per 10,000 tasks on the tokens of that run at the OpenRouter rate of 2026-10-02; metered means a run of that model, modelled means arithmetic on stated inputs. The private repo holds the build ledger; everything on this page has a probe folder in the public one.

How it works, in four steps

  1. Name the tasks you already send to a model. Triage, extraction, drafting, summaries. The one requirement: a person can say, case by case, whether the answer was right. A task nobody can check is not scored here, and the page says so. The eight tasks below are the demo set; a client's exam is never published.
  2. Write down what a correct answer looks like. Twenty to forty cases per task with their checks: the label, the fields, the facts that must appear, the tools that must be called. A third is held out and never tuned on. No model grades another model's answer, anywhere. Every local case runs three times at temperature 0 and counts only if all three agree.
  3. The cheapest model that passes takes the task. Every candidate sits the exam. The bar is the best score any model reached, or one case from it; models under it drop out; the cheapest left wins and its score is committed as the snapshot. One task drawn out, then the pick for all seven:

Then the loop: every model release, runtime bump or price change re-sits the exam per case and the report lists what moved in both directions. A challenger replaces the incumbent only if it passes every stable case the incumbent passes. On 2 October a runtime upgrade moved 1 of 220 cases, 0 held-out.

Evidence: the local champion ties or beats the hosted flagships on email triage, expense fields, reply drafts, the CRM brief over tool calls (where the 2B is the best model of any size) and the digest; it sits one case behind the top group on CRM field write-back and four behind on long call summaries. One panel per task; no aggregate across tasks, because a sum hides the row a buyer cares about. Local marks sit in the ≈0 lane. The hosted rows are one pass each (2026-10-02 ledger); the local rows are three fresh loads that agreed on every case.

The honest limit. On call summaries with numbers the best model of any tier passes 14 of 19; the local one 10. That band is closed until real transcripts exist. Six same-day runs on 1 September (three with the creator endpoint pinned, three not), on that day's case sets. pass^k is the share of cases passed on all k runs — the τ-bench reliability metric. The gate rule: a case counts only when three fresh loads agree; a challenger replaces the incumbent only if it passes every stable case the incumbent passes.

3. Four fine-tunes of the local champion, four refusals, and the cause named.

Evidence: LoRA on the 2B for the CRM brief, 30 training rows. v1–v3 trained with no prompt mask on rows that were 95% tool payload by characters, so the loss never saw the decisions: held-out 12→11, the adapter contradicting its own training row. v4 cut one example per assistant step with the prompt masked: it fixed the two-call case for the first time and taught a "call again" reflex, held-out 12→9. Every attempt was killed by its pre-registered rule (any stable held-out case down). metered

The same gate that picks a model refuses a fine-tune. What the loop can show honestly on synthetic cases is a smaller model holding the champion's score and a format failure fixed; an accuracy gain needs cases that are not at ceiling, which means a client's.

Three times the instrument was wrong

The build ledger stays private; three of its entries are public as post-mortems, each in the same shape: what we believed, what the probe showed, what changed.

  • The window, not the weights — three capability verdicts that were a 4,096-token truncation nobody had checked.
  • The gate said ok while five verdicts moved — an aggregate regression check, blind to cancelling flips; what replaced it.
  • A green gate that cannot go red — a test runner that reports "passed" by construction, and an answer key inside the instrument.
