> naming a client (a sales lead is referred to as "the lead"). Some links in the write-up

Local-first agent sandbox. Eight small office agents (email triage, CRM follow-up, expense
categorization, meeting recap, reply drafting, call-transcript summarisation, CRM fields from a call, request intake) run on local
models (2B to 14B on a 16 GB laptop; sizes are Gemma's effective sizes, Ollama lists
`gemma4:e2b-it-qat` as 2.3B effective, 5.1B with embeddings) or on hosted models through one config line. The agents
are deliberately boring. The exam suite around them is the point of this repo.

## Commands

```
pip install -r requirements.txt                       # requests, PyYAML; Ollama for local models
python3 docs/probes/pass3-column-2026-09-28/pass_k.py # finding 2 from committed files, no model needed
./.cline/test.sh                                      # the test gate: one process per file, exit code captured
python3 sandbox/runner.py list                        # agents, champions, exam modes
python3 sandbox/runner.py check <agent>               # re-sit one exam vs its snapshot, per case (needs Ollama + the champion)
python3 sandbox/runner.py diff <agent> --models m1,m2 # same exam, several models, one table
python3 sandbox/runner.py run <agent> --provider openrouter --model <id>   # a hosted model through the same entry point
```

`pytest` runs in CI but is blind to this repo's `check()`-style test files (post-mortem 3); the gate is `./.cline/test.sh`.
Hosted providers need their key in the environment; nothing is read from a file.

## Status


**Status (2026-10-06):** 8 agents, 220 committed cases (102 train / 118
held-out), 39 test files; the suite is judge-free and deterministic. Every snapshot is three fresh
loads at temperature 0 with a runtime stamp, so a runtime bump or a model swap re-sits the exam per case. Limitation, stated
plainly: held-out sets are 9–22 cases, so the suite ranks bad models out but cannot separate two good ones (the results
table prints how many candidates competed and calls a one-case gap noise), and every case input is hand-authored.
Getting real inputs in is the active work. The per-lane build ledger (post-mortems included) stays in the working repo.
